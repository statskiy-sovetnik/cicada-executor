# Договорённости по коду

## Типы

Типы не живут в файлах с кодом. Они лежат в `src/types/`, разбитые по
назначению:

```
db.ts        ряды таблиц, в snake_case — как их отдаёт SQLite
catalog.ts   представления записи наружу: DecodedAction, SpentRef
decode.ts    расшифровка делегаций и кейвитов
execute.ts   результат запуска исполнения
config.ts    конфигурация сети
http.ts      Result — ответ обработчика до сериализации
index.ts     реэкспорт
```

Исключение одно: типы контракта API выводятся из zod-схем в `src/schema.ts`
через `z.infer` и остаются там. Переносить их в `src/types/` нельзя — появится
второй источник истины, и схема с типом однажды разойдутся.

Обработчики маршрутов возвращают `Result`, а не пишут в `ServerResponse` сами:
отправку и обработку ошибок берёт на себя `server.ts`, поэтому у всех ответов
одна форма.

## Граница знания о фреймворке

Знание о Delegation Framework живёт только на пути **чтения** (`decode.ts`) и на
приёме подписи (`catalog.ts`). Путь исполнения остаётся транспортом поверх
непрозрачных байтов — ошибка в декодере не может породить неверную транзакцию
(4.8 спецификации).

## Состояние, выводимое запросом

Факты, которые можно вывести из журнала исполнений, не денормализуются флагами
на `actions`: израсходованность записи (5.7) считается запросом. Двух копий
одного факта быть не должно.

## Прочее

Адреса контрактов и тела URL — в `src/config.ts`, секреты — в `.env`.

Спецификация в `7702-demo/docs` — источник истины. Расхождение означает, что
надо поправить спецификацию, а не замолчать его.
